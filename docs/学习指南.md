## 第 0 章 这个项目到底是什么

### 0.1 一句话介绍

这是一个**用来练手的全栈小项目**：

- 后端：Django 4.2 提供 REST 接口，数据存进 MySQL；
- 异步：Celery 把耗时任务丢到后台，用 Redis 当队列；
- 前端：Vue 2.7 + Vite 写页面，调用后端接口；
- 环境：MySQL 和 Redis 都跑在 Docker 容器里，不污染你的电脑。

功能上实现了一个「笔记」的增删改查，加上**搜索、分页**，以及一个**先本地编辑、点按钮才同步到后端**的功能。

### 0.2 整体架构图

```text
┌──────────────────────────── 你的浏览器 ────────────────────────────┐
│  访问 http://localhost:5173                                        │
│  Vue 页面：服务状态 / Celery 任务 / 笔记 CRUD                      │
└───────────────────────────────┬────────────────────────────────────┘
                                │ 请求 /api/xxx
                                ▼
┌──────────────────────── Vite 开发服务器 :5173 ─────────────────────┐
│  把 /api 开头的请求转发（proxy）到 http://127.0.0.1:8000            │
└───────────────────────────────┬────────────────────────────────────┘
                                ▼
┌──────────────────────── Django 后端 :8000 ─────────────────────────┐
│  URL 路由 → View 视图 → Serializer 序列化 → Model/ORM              │
│                              │                  │                  │
│                              │                  ├──> MySQL :3307    │
│                              │                  │    （存笔记数据） │
│                              │                  │                  │
│                              └──> Celery 任务 ──┼──> Redis :6380    │
│                                   丢进队列        │    （队列+结果）  │
└──────────────────────────────────────────────────┼─────────────────┘
                                                   ▼
                                    ┌──────────────────────────┐
                                    │  Celery Worker 后台进程   │
                                    │  真正执行 add / slow_task │
                                    └──────────────────────────┘
```

### 0.3 端口和密码一览

| 服务 | 地址 | 账号 / 密码 | 说明 |
| --- | --- | --- | --- |
| Django 后端 | http://127.0.0.1:8000 | 无（接口允许匿名访问） | `python manage.py runserver` |
| Django 后台 | http://127.0.0.1:8000/admin/ | 你自己创建的超级用户 | 需要先 `createsuperuser` |
| 前端页面 | http://localhost:5173 | 无 | `npm run dev` |
| MySQL | 127.0.0.1:**3307** | 用户 `django`，密码 `gyc@0109` | Docker 容器 `django-study-mysql` |
| MySQL root | 127.0.0.1:3307 | `root` / `gyc@0109` | 仅本地学习用 |
| Redis | 127.0.0.1:**6380** | 密码 `gyc@0109` | Docker 容器 `django-study-redis` |

> 为什么 MySQL 用 3307 而不是 3306？
> 因为这台电脑的 3306 已经被系统自带的 MariaDB 占用，换个端口最省事。
> Redis 用 6380 而不是 6379 也是同样的道理，避免和本机已有服务冲突。

### 0.4 技术栈名词解释（先混个脸熟）

| 名词 | 通俗解释 |
| --- | --- |
| Django | Python 的 Web 框架，帮你处理网址、数据库、后台管理 |
| DRF（Django REST Framework） | Django 的插件，专门用来写返回 JSON 的接口 |
| ORM | 用 Python 类和对象操作数据库，不用手写 SQL |
| MySQL | 关系型数据库，数据最终存在这里 |
| Redis | 内存数据库，本项目里当缓存和 Celery 的队列 |
| Celery | 异步任务框架，把耗时操作放到后台进程执行 |
| Docker | 容器工具，把 MySQL/Redis 装进「盒子」里运行 |
| Vue | 前端框架，用数据驱动页面 |
| Vite | 前端开发和打包工具，启动快、支持热更新 |
| axios | 前端发 HTTP 请求的库 |

## 第 1 章 把项目跑起来（手把手）

> 这一章假设你在一台全新的 Linux 电脑上，从零开始。
> 如果容器和依赖都还在，只需要看 [1.7 日常启动](#17-日常启动只要四步)。

### 1.1 先确认三样东西

打开终端，依次执行：

```bash
# 1. Docker 是否可用
docker --version

# 2. Python 版本（需要 3.10 ~ 3.12，推荐 3.11）
python3 --version

# 3. Node.js 版本（需要 18 以上）
node --version
npm --version
```

本项目实际使用的版本：

- Python **3.11.13**（通过 pyenv 安装）
- Node.js 18+
- Docker 20+

> 为什么不直接用系统的 Python 3.14？
> Django 4.2 是 LTS 版本，不支持 Python 3.14，会报语法/依赖错误。
> 所以用 pyenv 装一个 3.11 的独立版本。

### 1.2 启动 MySQL 容器

先看看容器是不是已经存在：

```bash
docker ps -a
```

**情况 A：已经能看到 `django-study-mysql`**

直接启动即可：

```bash
docker start django-study-mysql
```

**情况 B：没有这个容器，需要新建**

```bash
docker run -d \
  --name django-study-mysql \
  -p 3307:3306 \
  -e MYSQL_ROOT_PASSWORD='gyc@0109' \
  -e MYSQL_DATABASE=django_study \
  -e MYSQL_USER=django \
  -e MYSQL_PASSWORD='gyc@0109' \
  mysql:8.4
```

参数解释：

- `-d`：后台运行；
- `--name`：给容器起名字，方便以后 `docker start/stop`；
- `-p 3307:3306`：把容器里的 3306 映射到电脑的 3307；
- `-e`：设置环境变量，MySQL 镜像首次启动时会据此创建数据库和用户。

> 如果拉取镜像时报网络错误（如 `EOF`），可以换国内镜像源：
>
> ```bash
> docker pull docker.m.daocloud.io/library/mysql:8.4
> docker tag docker.m.daocloud.io/library/mysql:8.4 mysql:8.4
> ```
>
> 然后再执行上面的 `docker run`。

### 1.3 启动 Redis 容器

**情况 A：容器已存在**

```bash
docker start django-study-redis
```

**情况 B：需要新建**

```bash
docker run -d \
  --name django-study-redis \
  -p 6380:6379 \
  redis:8.0-alpine \
  redis-server --requirepass 'gyc@0109' --appendonly yes
```

参数解释：

- `--requirepass`：给 Redis 设置密码；
- `--appendonly yes`：开启 AOF 持久化，重启后数据还在。

### 1.4 准备后端 Python 环境

```bash
# 进入后端目录
cd /home/gyc/Labs/Django-Study/backend

# 如果你还没装 pyenv，先装（已有可跳过）
# 然后用 pyenv 安装并指定 Python 3.11
pyenv install 3.11.13
pyenv local 3.11.13

# 创建虚拟环境（.venv 是这个项目专属的 Python 小房间）
/home/gyc/.pyenv/versions/3.11.13/bin/python -m venv .venv

# 激活虚拟环境（激活后命令行前面会出现 (.venv)）
source .venv/bin/activate

# 安装依赖
pip install -r requirements.txt
```

> 虚拟环境是什么？
> 可以理解为「这个项目专用的 Python 和第三方库」。
> 不影响系统 Python，也不会和别的项目打架。用完 `deactivate` 就退出。

如果 `pip install` 最后出现沙箱相关报错，但 `pip list` 能看到 Django，说明其实已经装成功了，可以继续。

### 1.5 配置 .env 文件

后端通过 `.env` 读取密码等配置。仓库里只提交了 `.env.example`，需要你自己复制一份：

```bash
cd /home/gyc/Labs/Django-Study/backend
cp .env.example .env
```

`.env` 的内容应该是：

```dotenv
DJANGO_SECRET_KEY=请替换为随机字符串
DJANGO_DEBUG=1

MYSQL_HOST=127.0.0.1
MYSQL_PORT=3307
MYSQL_DB=django_study
MYSQL_USER=django
MYSQL_PASSWORD=gyc@0109

REDIS_URL=redis://:gyc%400109@127.0.0.1:6380/0
REDIS_CACHE_URL=redis://:gyc%400109@127.0.0.1:6380/1
```

**重点：密码里的 `@` 必须写成 `%40`。**

因为 Redis 连接串的格式是：

```text
redis://:密码@主机:端口/库编号
```

`@` 是分隔符，密码里再出现 `@` 就会解析错乱。`%40` 是 `@` 的 URL 编码。

### 2.1 两个容易混淆的名字

- `config/` 是**项目级配置**（整个网站共用）。
- `core/` 是**业务模块**（这个网站自己的功能）。

Django 里可以有很多 app，比如以后可以加 `users/`、`orders/`，每个 app 负责一块业务。
本项目只有 `core` 一个 app。

### 2.2 建议的代码阅读顺序

1. `backend/core/models.py`：先看数据长什么样；
2. `backend/core/serializers.py`：看数据怎么变成 JSON；
3. `backend/core/views.py`：看接口逻辑；
4. `backend/core/urls.py` + `backend/config/urls.py`：看网址怎么对应到视图；
5. `backend/config/settings.py`：看全局配置；
6. `frontend/src/App.vue`：看页面怎么调用接口；
7. `backend/core/tasks.py` + `backend/config/celery.py`：看异步任务。

## 第 3 章 一次请求的完整旅程

以「前端加载笔记列表」为例：

```text
1. 浏览器访问 http://localhost:5173
   └─ Vite 返回 index.html + App.vue 编译后的 JS

2. App.vue 的 mounted() 执行：
   http.get('/notes/', { params: { page: 1 } })

3. axios 的 baseURL 是 /api，所以实际请求：
   GET http://localhost:5173/api/notes/?page=1

4. Vite 代理拦截 /api，转发到：
   GET http://127.0.0.1:8000/api/notes/?page=1

5. Django 收到请求，按 config/urls.py 匹配：
   /api/ → include('core.urls')

6. core/urls.py 里 router 匹配到 notes → NoteViewSet

7. DRF 调用 NoteViewSet.list()：
   - 从 MySQL 查 Note 数据
   - 应用搜索条件（如果有 ?search=）
   - 分页（每页 5 条）
   - 用 NoteSerializer 把对象转成 JSON

8. 返回 JSON：
   {
     "count": 7,
     "next": "http://127.0.0.1:8000/api/notes/?page=2",
     "previous": null,
     "results": [ {...}, {...} ]
   }

9. 前端把 data.results 赋给 this.notes，Vue 自动刷新表格。
```

理解这条链路之后，以后遇到问题就能判断是**前端、网络、后端还是数据库**哪一层出的错。

## 第 4 章 settings.py：项目的控制面板

文件位置：`backend/config/settings.py`

Django 启动时会先读它。下面挑最重要的配置解释。

### 4.1 BASE_DIR 和 .env

```python
BASE_DIR = Path(__file__).resolve().parent.parent
load_dotenv(BASE_DIR / ".env")
```

- `BASE_DIR` 是 `backend/` 目录的绝对路径；
- `load_dotenv` 把 `.env` 里的键值对读进环境变量；
- 后面用 `os.getenv("MYSQL_PASSWORD", "默认值")` 读取。

这样做的好处：密码不写死在代码里，也不会被提交到 GitHub。

### 4.2 INSTALLED_APPS

```python
INSTALLED_APPS = [
    "django.contrib.admin",
    "django.contrib.auth",
    ...
    "rest_framework",
    "corsheaders",
    "core",
]
```

只有写在这里的 app，Django 才会加载它的模型、路由等。
自己新建 app 后，**一定要记得加到这里**，否则数据库迁移会找不到表。

### 4.3 MIDDLEWARE

中间件是请求的「安检通道」：

- 请求进来：从上到下依次经过；
- 响应返回：从下到上依次离开。

`CorsMiddleware` 放在最上面，是为了让跨域预检请求（OPTIONS）尽早被处理。

### 4.4 DATABASES

```python
DATABASES = {
    "default": {
        "ENGINE": "django.db.backends.mysql",
        "NAME": os.getenv("MYSQL_DB", "django_study"),
        "USER": os.getenv("MYSQL_USER", "django"),
        "PASSWORD": os.getenv("MYSQL_PASSWORD", "gyc@0109"),
        "HOST": os.getenv("MYSQL_HOST", "127.0.0.1"),
        "PORT": os.getenv("MYSQL_PORT", "3307"),
        "OPTIONS": {"charset": "utf8mb4"},
    }
}
```

- `utf8mb4` 才能正常保存中文和 emoji；
- 端口 3307 对应 Docker 的映射。

### 4.5 CACHES（Redis）

```python
CACHES = {
    "default": {
        "BACKEND": "django.core.cache.backends.redis.RedisCache",
        "LOCATION": os.getenv("REDIS_CACHE_URL", "redis://:gyc%400109@127.0.0.1:6380/1"),
    }
}
```

健康检查接口会往这里写一个 `health=ok` 再读出来，验证 Redis 是否连通。

### 4.6 REST_FRAMEWORK（分页/搜索/权限）

```python
REST_FRAMEWORK = {
    "DEFAULT_PERMISSION_CLASSES": ["rest_framework.permissions.AllowAny"],
    "DEFAULT_PAGINATION_CLASS": "rest_framework.pagination.PageNumberPagination",
    "PAGE_SIZE": 5,
    "DEFAULT_FILTER_BACKENDS": [
        "rest_framework.filters.SearchFilter",
        "rest_framework.filters.OrderingFilter",
    ],
}
```

逐项解释：

- `AllowAny`：谁都能访问接口（学习项目图方便，上线要改）；
- `PageNumberPagination`：按页码分页；
- `PAGE_SIZE: 5`：每页 5 条；
- `SearchFilter`：支持 `?search=关键词`；
- `OrderingFilter`：支持 `?ordering=字段`。

### 4.7 CELERY 配置

```python
CELERY_BROKER_URL = os.getenv("REDIS_URL", "redis://:gyc%400109@127.0.0.1:6380/0")
CELERY_RESULT_BACKEND = CELERY_BROKER_URL
CELERY_TASK_TRACK_STARTED = True
CELERY_TIMEZONE = TIME_ZONE
```

- **broker**：任务队列，用 Redis 的 0 号库；
- **result backend**：任务结果也存 Redis，前端才能查；
- `TRACK_STARTED`：任务开始执行时状态从 `PENDING` 变 `STARTED`。

> 注意：Celery 和缓存用了 Redis 的不同库（0 和 1），
> 这样任务数据不会和缓存数据混在一起。

## 第 5 章 Model 与数据库迁移

### 5.1 ORM 是什么

传统写法要手写 SQL：

```sql
CREATE TABLE note (
  id INT PRIMARY KEY AUTO_INCREMENT,
  title VARCHAR(100) NOT NULL,
  content TEXT
);
```

Django 的 ORM 让你写 Python 类：

```python
class Note(models.Model):
    title = models.CharField("标题", max_length=100)
    content = models.TextField("内容", blank=True)
    created_at = models.DateTimeField("创建时间", auto_now_add=True)
```

Django 会帮你翻译成 SQL。

| Python | 数据库 |
| --- | --- |
| 类 `Note` | 表 `core_note` |
| 属性 `title` | 字段 `title` |
| 一个 `Note()` 对象 | 一行数据 |
| `Note.objects.all()` | `SELECT * FROM core_note` |

### 5.2 本项目唯一的表

文件：`backend/core/models.py`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | BigAutoField | 主键，自增，Django 自动加 |
| `title` | CharField(100) | 标题，必填 |
| `content` | TextField | 内容，可为空 |
| `created_at` | DateTimeField | 创建时间，自动写入 |

`Meta.ordering = ["-id"]` 表示查询默认按 id 倒序，最新的排最前面。

### 5.3 迁移（migration）是什么

迁移文件记录「数据库结构要怎么变」，相当于数据库的版本管理。

改了 `models.py` 之后，必须执行两条命令：

```bash
python manage.py makemigrations   # 生成迁移文件（只写文件，不动数据库）
python manage.py migrate          # 真正执行到 MySQL
```

可以这样记：

- `makemigrations` = 写施工图纸；
- `migrate` = 按图纸施工。

### 5.4 常用 ORM 操作

进入 Django 交互式 shell：

```bash
python manage.py shell
```

```python
from core.models import Note

# 新增
Note.objects.create(title="第一条", content="Hello")

# 查询全部
Note.objects.all()

# 条件查询
Note.objects.filter(title__contains="Django")

# 改
n = Note.objects.first()
n.title = "新标题"
n.save()

# 删
n.delete()
```

这里看到的 `objects` 叫「管理器」，所有数据库操作都从它开始。

## 第 6 章 Serializer：模型和 JSON 的翻译官

文件：`backend/core/serializers.py`

### 6.1 为什么需要它

- 数据库里是 Python 对象；
- 网络上传输的是 JSON 文本；
- 两者需要互相转换，并且要校验前端传来的数据。

Serializer 就干这三件事：

```text
前端 JSON  ──校验──> Python 对象 ──> 存数据库    （反序列化）
数据库对象 ──转换──> Python 字典 ──> JSON 响应   （序列化）
```

### 6.2 本项目的代码

```python
class NoteSerializer(serializers.ModelSerializer):
    class Meta:
        model = Note
        fields = ["id", "title", "content", "created_at"]
        read_only_fields = ["id", "created_at"]
```

- `model = Note`：按哪个模型生成字段；
- `fields`：接口里暴露哪些字段；
- `read_only_fields`：客户端不能自己设置，由数据库生成。

`ModelSerializer` 会自动继承模型上的校验规则，例如 `title` 最长 100 字。

### 6.3 校验失败会怎样

比如 POST 一个没有 `title` 的数据：

```bash
curl -X POST http://127.0.0.1:8000/api/notes/ \
  -H 'Content-Type: application/json' \
  -d '{"content":"没有标题"}'
```

返回 400：

```json
{"title": ["该字段是必填项。"]}
```

这就是序列化器在帮你把关。

## 第 9 章 分页与搜索是怎么实现的

### 9.1 后端配置

在 `settings.py`：

```python
REST_FRAMEWORK = {
    "DEFAULT_PAGINATION_CLASS": "rest_framework.pagination.PageNumberPagination",
    "PAGE_SIZE": 5,
    "DEFAULT_FILTER_BACKENDS": [
        "rest_framework.filters.SearchFilter",
        "rest_framework.filters.OrderingFilter",
    ],
}
```

在 `views.py`：

```python
search_fields = ["title", "content"]
ordering_fields = ["id", "created_at", "title"]
```

`search_fields` 告诉 DRF：`?search=xxx` 要去哪些字段里找。

### 9.2 前端怎么传参数

```js
const { data } = await http.get('/notes/', {
  params: {
    search: this.search || undefined,
    page: this.page
  }
})
```

当 `search` 是空字符串时传 `undefined`，axios 会自动忽略这个参数。

### 9.3 后端返回什么

分页后返回的不是数组，而是一个对象：

```json
{
  "count": 12,
  "next": "http://127.0.0.1:8000/api/notes/?page=2",
  "previous": null,
  "results": [
    { "id": 12, "title": "...", "content": "...", "created_at": "..." }
  ]
}
```

- `count`：总条数；
- `next` / `previous`：上一页/下一页地址；
- `results`：当前页的数据。

所以前端必须读 `data.results`，不能直接把 `data` 当数组用。

### 9.4 总页数怎么算

```js
totalPages() {
  return Math.max(1, Math.ceil(this.total / this.pageSize))
}
```

- `Math.ceil` 向上取整：12 条、每页 5 条 → 3 页；
- `Math.max(1, ...)` 保证至少显示 1 页，避免出现「第 1 / 0 页」。

### 9.5 搜索的匹配规则

`SearchFilter` 默认使用 `icontains`：

- 不区分大小写；
- 只要字段里包含关键词就算命中。

等价 SQL：

```sql
SELECT * FROM core_note
WHERE title LIKE '%关键词%' OR content LIKE '%关键词%';
```

### 9.6 用 curl 自己试

```bash

curl 'http://127.0.0.1:8000/api/notes/?page=1'

# 搜索 django
curl 'http://127.0.0.1:8000/api/notes/?search=django'

# 搜索中文（需要 URL 编码，或者让 curl 自己处理）

# 排序
```

## 第 10 章 Celery：把慢活丢到后台

### 10.1 为什么需要异步任务

假设「发送邮件」要 3 秒。
如果直接在接口里执行，用户点按钮后要干等 3 秒，页面像卡住一样。

异步的思路：

1. 接口只负责把任务「丢进队列」，立刻返回；
2. 另一个后台进程（worker）慢慢执行；
3. 前端隔一会儿来问一次「做完了吗」。

### 10.2 三个角色

| 角色 | 在本项目里 | 作用 |
| --- | --- | --- |
| 任务生产者 | Django 视图调用 `add.delay()` | 把任务写进队列 |
| 队列（broker） | Redis 0 号库 | 存放待执行任务 |
| 消费者（worker） | `celery -A config worker` 进程 | 取任务并执行 |

### 10.3 代码在哪

`backend/core/tasks.py`：

```python
@shared_task
def add(a, b):
    return a + b

@shared_task
def slow_task(seconds=3):
    time.sleep(seconds)
    return f"已完成 {seconds} 秒的耗时任务"
```

`backend/config/celery.py`：

```python
app = Celery("django_study")
app.config_from_object("django.conf:settings", namespace="CELERY")
app.autodiscover_tasks()
```

- `namespace="CELERY"`：让 Celery 读取 `settings.py` 里所有 `CELERY_` 开头的配置；
- `autodiscover_tasks()`：自动去每个 app 的 `tasks.py` 里找任务。

### 10.4 两种调用方式的区别

```python
add(1, 2)        # 同步：当前进程立刻算，阻塞
add.delay(1, 2)  # 异步：丢进 Redis，立刻返回 task 对象
```

`.delay()` 返回的对象里有个 `.id`，用它就能查结果。

### 10.5 任务状态

| 状态 | 含义 |
| --- | --- |
| PENDING | 排队中，或 worker 没启动 |
| STARTED | 正在执行 |
| SUCCESS | 成功，结果在 `result` |
| FAILURE | 失败，错误在 `result` |

> 如果任务一直 PENDING，先检查 Celery worker 终端是不是还开着。

### 10.6 前端怎么拿结果

前端没有「服务器主动推送」，所以用**轮询**：

```js
for (let i = 0; i < 10; i += 1) {
  await new Promise((resolve) => setTimeout(resolve, 800))
  const { data } = await http.get(`/tasks/${taskId}/`)
  this.task = data
  if (data.status === 'SUCCESS' || data.status === 'FAILURE') return
}
```

也就是每 800 毫秒问一次，最多问 10 次。

### 10.7 手动体验

```bash
# 提交任务
curl -X POST http://127.0.0.1:8000/api/tasks/add/ \
  -H 'Content-Type: application/json' \
  -d '{"a": 7, "b": 35}'

# 返回 {"task_id":"xxxx"}

# 查结果
curl http://127.0.0.1:8000/api/tasks/xxxx/
```

## 第 12 章 手动同步功能拆解

这是本项目最值得学习的一段交互设计。

### 12.1 需求

普通 CRUD 是「输入框一改，立刻发请求」。
但用户希望：

1. 先在页面上自由编辑；
2. 编辑过程中**不请求后端**；
3. 点「同步」按钮时，才一次性把改动写入数据库。

### 12.2 数据结构设计

`App.vue` 里用 `edits` 保存草稿：

```js
edits: {
  3: {
    original: { title: "旧标题", content: "旧内容" },  // 进入编辑时的原值
    draft:    { title: "新标题", content: "新内容" }   // 正在编辑的草稿
  }
}
```

为什么要同时存 `original` 和 `draft`？

- `original` 用来判断「到底改没改」；
- 如果用户点开编辑又原样改回去，就不应该算作待同步。

### 12.3 四个关键方法

**进入编辑 `startEdit`**

```js
startEdit(note) {
  this.$set(this.edits, note.id, {
    original: { title: note.title, content: note.content },
    draft: { title: note.title, content: note.content }
  })
}
```

**撤销单行 `cancelEdit`**

```js
cancelEdit(id) {
  this.$delete(this.edits, id)
}
```

**判断是否真的改过 `isEntryDirty`**

```js
isEntryDirty(entry) {
  return entry.draft.title !== entry.original.title ||
         entry.draft.content !== entry.original.content
}
```

**同步 `syncAll`**

```js
async syncAll() {
  const ids = this.dirtyIds
  if (!ids.length || this.syncing) return

  this.syncing = true
  try {
    await Promise.all(
      ids.map((id) => http.patch(`/notes/${id}/`, this.edits[id].draft))
    )
    this.syncMsg = `已同步 ${ids.length} 条到 MySQL`
    this.edits = {}
    this.loadNotes()
  } catch (err) {
    this.syncMsg = `同步失败：${err.message}`
  } finally {
    this.syncing = false
  }
}
```

逐行解释：

- `dirtyIds`：只挑出真正改过的 id；
- `Promise.all`：把所有 PATCH 请求**同时**发出去；
- 全部成功后才清空草稿并重新加载列表；
- `finally`：不管成功失败都恢复按钮状态，防止一直卡在「同步中」。

### 12.4 为什么用 PATCH 而不是 PUT

- `PUT` 是**全量更新**，要求把所有字段都传过去；
- `PATCH` 是**局部更新**，只传要改的字段。

这里只改标题/内容，用 PATCH 更合适。

### 12.5 界面上的反馈

- 改过的行会加浅黄底色（`:class="{ dirty: isDirty(note.id) }"`）；
- 按钮上显示待同步数量：`同步到后端（2）`；
- 没有改动时按钮是禁用状态；
- 同步成功后显示「已同步 N 条到 MySQL」。

## 第 13 章 前后端如何联调（代理与跨域）

### 13.1 什么是跨域

浏览器规定：
`http://localhost:5173` 的页面，默认不能直接请求 `http://127.0.0.1:8000` 的接口。
协议、域名、端口三者只要有一个不同，就算「跨域」。

### 13.2 本项目的两种解决方式

**开发环境：Vite 代理（主要方式）**

```js
proxy: {
  '/api': {
    target: 'http://127.0.0.1:8000',
    changeOrigin: true
  }
}
```

浏览器只访问 5173，看起来是同源；
Vite 在服务器内部把请求转发到 8000。

**后端：CORS 配置（兜底）**

```python
CORS_ALLOWED_ORIGINS = [
    "http://localhost:5173",
    "http://127.0.0.1:5173",
]
```

这样即使前端直接请求 8000，后端也会返回允许跨域的响应头。

### 13.3 为什么代理里没有 rewrite

因为后端接口本身就是 `/api/` 开头：

- 前端请求 `/api/notes/`；
- 代理原样转发到 `http://127.0.0.1:8000/api/notes/`；
- 正好匹配 Django 路由。

如果后端接口没有 `/api` 前缀，才需要 `rewrite: path => path.replace(/^\/api/, '')`。

### 13.4 如何确认代理生效

```bash
curl http://localhost:5173/api/health/
```

如果返回和直接访问 8000 一样的结果，说明代理正常。

## 第 15 章 常见问题排查手册

### 15.1 页面显示「请求失败」

按顺序排查：

1. Django 后端终端是否还在运行（:8000）；
2. Vite 终端是否还在运行（:5173）；
3. 打开 <http://127.0.0.1:8000/api/health/> 看后端本身是否正常；
4. 看浏览器开发者工具 → Network，确认请求地址和状态码。

### 15.2 服务状态里 `"db": false`

MySQL 没连上。检查：

```bash
docker ps | grep mysql          # 容器是否在运行
docker start django-study-mysql # 没运行就启动
```

再确认 `backend/.env` 里的端口是 `3307`、密码是 `gyc@0109`。

### 15.3 服务状态里 `"redis": false`

```bash
docker ps | grep redis
docker start django-study-redis
```

并确认 `.env` 里密码写的是 `gyc%400109`（`@` 必须转义）。

### 15.4 任务一直 PENDING

原因通常是 Celery worker 没启动。

```bash
cd backend
source .venv/bin/activate
celery -A config worker -l info
```

看到 `ready.` 后再提交任务。

### 15.5 `docker compose` 命令不存在

这台机器的 Docker 没装 compose 插件，直接用等价的 `docker run` / `docker start` 即可（见第 1 章）。

### 15.6 拉取镜像报 `EOF` 或超时

使用国内镜像：

```bash
docker pull docker.m.daocloud.io/library/mysql:8.4
docker tag docker.m.daocloud.io/library/mysql:8.4 mysql:8.4

docker pull docker.m.daocloud.io/library/redis:8.0-alpine
docker tag docker.m.daocloud.io/library/redis:8.0-alpine redis:8.0-alpine
```

### 15.7 Django 报 Python 版本相关的错

Django 4.2 不支持 Python 3.13/3.14。确认虚拟环境用的是 3.11：

```bash
cd backend
source .venv/bin/activate
python --version
```

应该显示 `Python 3.11.x`。

### 15.8 端口被占用

```bash
# 查看 8000 / 5173 被谁占用
ss -lptn 'sport = :8000'
ss -lptn 'sport = :5173'
```

换端口启动：

```bash
python manage.py runserver 8001
npm run dev -- --port 5174
```

注意：换端口后 Vite 代理目标、CORS 白名单也要相应调整。

### 15.9 前端改了编辑框，页面不更新

大概率是直接给对象新增属性了。用 `this.$set` / `this.$delete`（见 11.6）。

### 15.10 迁移时报「表已存在」或字段冲突

```bash
# 查看迁移状态
python manage.py showmigrations core

# 如果只是本地学习数据，可以重置（会删数据！）
python manage.py migrate core zero
python manage.py migrate
```

### 15.11 `pip install` 最后报沙箱错误

如果 `pip list` 里已经能看到 Django、celery 等包，说明依赖其实装好了，可以继续。
这是运行环境的沙箱提示，不是项目代码问题。

### 15.12 中文搜索搜不到

确认请求参数经过了 URL 编码。用 curl 时推荐：

```bash
curl --get --data-urlencode 'search=测试' 'http://127.0.0.1:8000/api/notes/'
```

浏览器里 axios 会自动编码，不需要手动处理。

## 第 18 章 推荐练习路线

按难度从低到高，建议自己动手改代码：

### 练习 1：改页面文案

修改 `frontend/src/App.vue` 里的标题和提示语，观察热更新。

### 练习 2：加一个字段

给 `Note` 加一个 `author` 字段：

1. 改 `models.py`；
2. `makemigrations` + `migrate`；
3. 改 `serializers.py` 的 `fields`；
4. 改前端表格和编辑表单。

### 练习 3：改每页条数

把 `settings.py` 的 `PAGE_SIZE` 改成 10，
同时把 `App.vue` 的 `pageSize` 改成 10。思考：为什么两边都要改？

### 练习 4：加一个「批量删除」

后端不需要改，DRF 已支持逐条 DELETE。
前端循环调用 `http.delete` 即可，注意用 `Promise.all`。

### 练习 5：加一个真正的异步任务

比如「统计当前笔记总数」：

1. 在 `core/tasks.py` 写一个 `count_notes` 任务；
2. 写一个视图调用 `.delay()`；
3. 前端轮询结果。

### 练习 6：给接口加登录保护

把 `DEFAULT_PERMISSION_CLASSES` 改成 `IsAuthenticated`，
观察哪些接口开始返回 401，再学习 DRF 的认证机制。

### 练习 7：把前端打包部署

```bash
cd frontend
npm run build
```

把 `dist/` 里的文件交给 Nginx，学习生产环境部署。
