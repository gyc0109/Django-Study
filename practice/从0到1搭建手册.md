## 怎么用这份文档

### 每个 STEP 都是固定三行结构

```text
STEP x.y  一句话说明这步干什么
  ▸ 敲：要执行的命令 / 要写入的代码
  ▸ 看：正常情况下你应该看到的输出
  ▸ 懂：为什么这么做 + 最容易踩的坑（1~3 行，想深入看教学文档第 N 章）
```

### 三个必须遵守的纪律

| 纪律 | 原因 | 违反的后果 |
| --- | --- | --- |
| **一个阶段验收通过再进下一阶段** | 后面的阶段依赖前面的成果 | 报错堆在一起，根本不知道是哪步错的 |
| **每开一个新终端，先 `source .venv/bin/activate`** | 依赖装在 `.venv` 里 | `ModuleNotFoundError: No module named 'django'` |
| **命令里的路径结尾 `/` 不要自己删** | DRF 路由都带尾斜杠 | `POST /api/books` 直接 500 |

### 三个终端的分工（从阶段 10 开始长期保持）

| 终端 | 跑什么 | 端口 | 关掉会怎样 |
| --- | --- | --- | --- |
| 终端 A | `python manage.py runserver 127.0.0.1:8001` | 8001 | 接口全挂 |
| 终端 B | `celery -A config worker -l info` | 无 | 异步任务永远 PENDING |
| 终端 C | `npm run dev` | 5174 | 页面打不开 |

### 本文用到的标记

- `✅` 本阶段验收动作（必须通过）
- `❌` 常见失败现象
- `★` 反直觉、容易错的点
- `▸` 一个操作步骤

## 阶段 0　开工前的 5 项检查

> **目标**：确认机器上该有的东西都有。缺什么现在补，别等到阶段 5 才发现。
> **对应**：教学文档第 2 章、附录 D（Docker 安装）。

### STEP 0.1　确认 Docker 在跑，两个容器都活着

▸ 敲：

```bash
docker ps --filter name=django-study --format 'table {{.Names}}\t{{.Status}}\t{{.Ports}}'
```

▸ 看（两行，都必须是 `Up`）：

```text
NAMES                 STATUS          PORTS
django-study-mysql    Up 2 hours      0.0.0.0:3307->3306/tcp, :::3307->3306/tcp
django-study-redis    Up 2 hours      0.0.0.0:6380->6379/tcp, :::6380->6379/tcp
```

▸ 懂：
- **3307 / 6380 是宿主机端口**，容器内部还是 3306 / 6379。之所以错开，是因为本机可能已经装了原生 MySQL/Redis 占着默认端口。
- ❌ 如果一行都没有：先 `docker ps -a` 看容器是否存在；存在就 `docker start django-study-mysql django-study-redis`；不存在就要按教学文档附录 D.6 重新 `docker run`。
- ❌ 报 `Cannot connect to the Docker daemon`：Docker 服务没启动，`sudo systemctl start docker`。

### STEP 0.2　确认 MySQL 能登进去

▸ 敲：

```bash
docker exec -it django-study-mysql mysql -uroot -pHenhaoji@119 -e "SELECT VERSION();"
```

▸ 看：

```text
+-----------+
| VERSION() |
+-----------+
| 8.4.x     |
+-----------+
```

▸ 懂：
- `-p` 和密码之间**不能有空格**（写成 `-p Henhaoji@119` 会被当成「数据库名」）。
- 密码含 `@` 时，如果是在宿主机用 `mysql` 客户端连接，必须用单引号包起来：`-p'Henhaoji@119'`。

### STEP 0.3　确认 Redis 能 PING 通

▸ 敲：

```bash
docker exec -it django-study-redis redis-cli -a 'Henhaoji@119' PING
```

▸ 看：

```text
PONG
```

▸ 懂：
- `-a` 后面跟密码；`Warning: Using a password with '-a' ...` 这行警告可以忽略。
- ❌ `NOAUTH Authentication required` = 没带密码；`WRONGPASS` = 密码错了。

### STEP 0.4　确认 Python 版本（必须 3.8 ~ 3.12）

▸ 敲：

```bash
python3 --version
pyenv versions
```

▸ 看：

```text
Python 3.11.13        ← pyenv 里要有这一行（前面带 * 表示当前在用）
```

▸ 懂：
- **Django 4.2 不支持 Python 3.13+**，用 3.13 会出现各种莫名的 `ImportError`。
- 没有 3.11 就装：`pyenv install 3.11.13`（教学文档 2.3）。

### STEP 0.5　确认 Node 版本

▸ 敲：

```bash
node -v && npm -v
```

▸ 看：

```text
v18.x 以上（v20 / v22 都行）
```

▸ 懂：
- Vite 5 要求 Node 18+。
- ★ 如果 Node 是 18+，注意后面代理要写 `127.0.0.1` 而不是 `localhost`（Node 会优先解析到 IPv6 `::1`，而 Django 只监听 IPv4，导致 `ECONNREFUSED`）。

### ✅ 阶段 0 验收

上面 5 条命令，每条都有正常输出。有一条不行就**停下来修**，不要往下走。

## 阶段 1　让数据库就位

> **目标**：在已有的 MySQL 实例里，为本项目单独建一个库 `practice_db`。
> **对应**：教学文档 2.2、附录 E。
> **产出**：`practice_db` 数据库 + `django` 用户对它的全部权限。

### STEP 1.1　建库 + 授权

▸ 敲（整段复制，`-e` 后面的 SQL 是双引号包着的多行）：

```bash
docker exec -it django-study-mysql mysql -uroot -pHenhaoji@119 -e "
CREATE DATABASE IF NOT EXISTS practice_db
  DEFAULT CHARACTER SET utf8mb4
  COLLATE utf8mb4_unicode_ci;
GRANT ALL PRIVILEGES ON practice_db.* TO 'django'@'%';
FLUSH PRIVILEGES;
"
```

▸ 看：没有任何输出就是成功（`-e` 执行完就退出）。

▸ 懂：
- `IF NOT EXISTS`：重复执行不会报「库已存在」，方便你反复练。
- `utf8mb4`：唯一能存 emoji 😀 和生僻字的字符集。老的 `utf8`（3 字节）存 emoji 会报 `Incorrect string value`。
- 为什么不用 root 连数据库？Django 里配的是 `django` 账号，权限最小化。
- `GRANT ... TO 'django'@'%'`：`%` 表示允许从任意主机连（因为是容器，连接来源的 IP 不固定）。

### STEP 1.2　验证库存在

▸ 敲：

```bash
docker exec -it django-study-mysql mysql -uroot -pHenhaoji@119 -e "SHOW DATABASES;"
```

▸ 看（列表里要有 `practice_db`）：

```text
+--------------------+
| Database           |
+--------------------+
| django_study       |   ← 另一个项目在用，别动
| practice_db        |   ← 本项目
| ...
+--------------------+
```

### STEP 1.3　用 `django` 账号登录一次（提前排雷）

▸ 敲：

```bash
docker exec -it django-study-mysql mysql -udjango -pHenhaoji@119 -e "USE practice_db; SELECT DATABASE();"
```

▸ 看：

```text
+------------+
| DATABASE() |
+------------+
| practice_db|
+------------+
```

▸ 懂：
- 这一步很关键。如果这里就失败，阶段 5 的 `migrate` 一定会失败，而且报错信息很长很难懂。**先在数据库层面把权限问题解决掉。**
- ❌ `Access denied for user 'django'`：说明 STEP 1.1 的 `GRANT` 没执行成功（注意 `@'%'` 引号别丢）。

### ✅ 阶段 1 验收

`SHOW DATABASES` 里有 `practice_db`，且 `django` 账号能进去。

## 阶段 2　Python 环境

> **目标**：给后端一个干净的、独立的 Python 环境，并把依赖装齐。
> **对应**：教学文档 2.4、2.5。
> **产出**：`practice/backend/.venv/` + 29 个第三方包。

### STEP 2.1　建目录

▸ 敲：

```bash
mkdir -p /home/gyc/Labs/Django-Study/practice/backend
cd /home/gyc/Labs/Django-Study/practice/backend
```

▸ 懂：`-p` 的作用是「父目录不存在就一起创建，已存在也不报错」。

### STEP 2.2　写依赖清单 `requirements.txt`

▸ 在 `practice/backend/` 下新建 `requirements.txt`，内容：

```text
Django==4.2.30
djangorestframework==3.17.2
django-cors-headers==4.9.0
celery==5.7.0
redis==8.1.0
PyMySQL==1.2.3
python-dotenv==1.2.4
```

▸ 懂：
- **版本号全部写死**。不写死的话，半年后别人 `pip install` 装到的是新版，可能跑不起来。
- 只写我们**直接使用**的包。像 `kombu`、`billiard` 这些是 Celery 的依赖，pip 会自动装，不用列。
- 为什么用 `PyMySQL` 不用 `mysqlclient`：后者是 C 扩展，要本机有 MySQL 头文件，新手十有八九卡在编译报错。

### STEP 2.3　创建并激活虚拟环境

▸ 敲：

```bash
python3.11 -m venv .venv
source .venv/bin/activate
python -V
```

▸ 看：

```text
(.venv) ...              ← 命令行前面多出这个前缀
Python 3.11.13
```

▸ 懂：
- **目录名就叫 `.venv`**（前面有点）。很多教程写 `venv`，如果你照着别的教程敲会建出两个目录，互相干扰。
- ★ `source` 只对**当前这个终端**生效。新开终端必须重新 `source`，这是新手最常犯的错，症状就是「明明装过 django 却说找不到」。

### STEP 2.4　安装依赖

▸ 敲（国内网络加镜像，会快很多）：

```bash
pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple
```

▸ 看：

```text
Successfully installed Django-4.2.30 PyMySQL-1.2.3 celery-5.7.0 ... 
```

▸ 懂：
- ❌ `No module named pip`：虚拟环境建坏了，删掉 `.venv` 重来。
- ❌ 卡在下载：换镜像源；或者加 `--default-timeout=120`。

### STEP 2.5　验证

▸ 敲：

```bash
python -c "import django, rest_framework, celery, pymysql, dotenv; print('Django', django.get_version())"
```

▸ 看：

```text
Django 4.2.30
```

### ✅ 阶段 2 验收

命令行前面有 `(.venv)`，且上面那条命令打印 `Django 4.2.30`。

## 阶段 3　项目骨架

> **目标**：用 Django 官方命令生成目录结构，再手工补上 Django 不会自动生成的文件。
> **对应**：教学文档第 3 章。
> **产出**：`config/`（配置包）+ `library/`（业务 app）+ `manage.py`。

### STEP 3.1　生成项目骨架

▸ 敲（确认当前在 `practice/backend/`、虚拟环境已激活）：

```bash
django-admin startproject config .
```

▸ 看（目录变成）：

```text
backend/
├── config/
│   ├── __init__.py
│   ├── asgi.py
│   ├── settings.py
│   ├── urls.py
│   └── wsgi.py
└── manage.py
```

▸ 懂：
- ★ 命令最后那个**点**特别重要。漏了它，会生成 `backend/config/config/settings.py`，多套一层，后面所有命令的模块路径都要改。
- 为什么项目包叫 `config` 而不是项目名？因为它是「配置包」，名字统一，换个项目也不用改命令。Django 允许任意名字。

### STEP 3.2　生成业务 app

▸ 敲：

```bash
python manage.py startapp library
```

▸ 看（多出一个 `library/` 目录）：

```text
library/
├── migrations/
│   └── __init__.py
├── admin.py
├── apps.py
├── models.py
├── tests.py
└── views.py
```

▸ 懂：
- Django 只生成这 6 个文件。**`serializers.py`、`tasks.py`、`urls.py`、`management/` 都要自己建**（阶段 7、8、10、13 会建）。
- 为什么不全自动生成？因为小项目可以不用 DRF / Celery，官方不假设你一定要用。

### STEP 3.3　建 4 个空文件 / 目录

▸ 敲：

```bash
touch library/serializers.py library/tasks.py library/urls.py
mkdir -p library/management/commands
touch library/management/__init__.py library/management/commands/__init__.py
```

▸ 看：

```text
library/
├── management/
│   ├── __init__.py          ← 必须有
│   └── commands/
│       └── __init__.py      ← 必须有
├── serializers.py
├── tasks.py
└── urls.py
```

▸ 懂：
- ★ `management/commands/` 这两个 `__init__.py` 都不能少。少了，`python manage.py seed_demo` 会报 `Unknown command`。
- ★ 目录名 `management` 和 `commands` 都是 Django 写死的，改成 `mgmt` 就找不到。
- 现在先建空文件，是为了后面写代码时文件已经在那儿，不用来回建。

### STEP 3.4　把 app 和第三方库注册进 `INSTALLED_APPS`

▸ 打开 `config/settings.py`，把 `INSTALLED_APPS` 改成：

```python
INSTALLED_APPS = [
    "django.contrib.admin",
    "django.contrib.auth",
    "django.contrib.contenttypes",
    "django.contrib.sessions",
    "django.contrib.messages",
    "django.contrib.staticfiles",
    "rest_framework",
    "corsheaders",
    "library",
]
```

▸ 懂：
- 前 6 个是 Django 自带的，别删（删了 admin、登录、session 全没了）。
- ★ 不注册 `library`，`makemigrations` 会提示「No changes detected」，表永远建不出来——这是最常见的「为什么我的表没建」原因。

### STEP 3.5　先跑一次检查

▸ 敲：

```bash
python manage.py check
```

▸ 看：

```text
System check identified no issues (0 silenced).
```

▸ 懂：
- ❌ 这时如果报 `ModuleNotFoundError: No module named 'MySQLdb'`，**先别慌**，阶段 4.2 会解决（现在还没写 `config/__init__.py`）。
- 如果报 `No module named 'rest_framework'`，说明没装依赖，回阶段 2。

### ✅ 阶段 3 验收

`config/` 和 `library/` 都在，`library/` 下有 5 个我们要补的文件/目录，`manage.py check` 无 issue。

## 阶段 4　配置四件套

> **目标**：把 Django 从「默认 SQLite 空壳」变成「连 MySQL + 连 Redis + 装了 DRF/CORS + 有 Celery」。
> **对应**：教学文档第 3.3~3.4、第 4 章（settings 逐段讲解）。
> **产出**：`.env`、`settings.py`（改造）、`config/__init__.py`、`config/celery.py`、`config/urls.py`。

### STEP 4.1　写 `.env`

▸ 在 `practice/backend/` 下新建 `.env`：

```dotenv
DJANGO_SECRET_KEY=练习项目请换成随机字符串
DJANGO_DEBUG=1

MYSQL_HOST=127.0.0.1
MYSQL_PORT=3307
MYSQL_DB=practice_db
MYSQL_USER=django
MYSQL_PASSWORD=Henhaoji@119

REDIS_CACHE_URL=redis://:Henhaoji%40119@127.0.0.1:6380/2
REDIS_URL=redis://:Henhaoji%40119@127.0.0.1:6380/3
```

▸ 再复制一份给团队（不含真实密钥也行，本项目密码是练习用的）：

```bash
cp .env .env.example
```

▸ 懂：
- **为什么密码不写在代码里？** 代码要传 GitHub，`.env` 被 `.gitignore` 忽略。上线时只改环境变量，不改代码。
- ★ Redis URL 里的 `@` 必须写成 `%40`。格式是 `redis://:密码@主机:端口/库号`，密码里出现 `@` 会把地址解析错。

## 阶段 5　数据模型与建表

> **目标**：用 Python 类描述两张表，让 Django 生成 SQL 并真正在 MySQL 里建表。
> **对应**：教学文档第 5 章（为什么两张表）、第 6 章（migrations 原理）。
> **产出**：`library/models.py` + `library/migrations/0001_initial.py` + MySQL 里的 2 张业务表。

### STEP 5.1　写 `library/models.py`

▸ 完整内容（可直接复制，逐行注释见 [models.py](./backend/library/models.py)）：

```python
from django.db import models


class Category(models.Model):
    """图书分类。数据库表名：library_category"""

    name = models.CharField("分类名称", max_length=50, unique=True)
    created_at = models.DateTimeField("创建时间", auto_now_add=True)

    class Meta:
        ordering = ["id"]
        verbose_name = "分类"
        verbose_name_plural = "分类"

    def __str__(self):
        return self.name


class Book(models.Model):
    """图书。数据库表名：library_book"""

    title = models.CharField("书名", max_length=120)
    author = models.CharField("作者", max_length=80, blank=True)
    price = models.DecimalField("价格", max_digits=8, decimal_places=2, default=0)
    stock = models.PositiveIntegerField("库存", default=0)
    category = models.ForeignKey(
        Category,
        verbose_name="分类",
        related_name="books",
        on_delete=models.PROTECT,
        null=True,
        blank=True,
    )
    created_at = models.DateTimeField("创建时间", auto_now_add=True)

    class Meta:
        ordering = ["-id"]
        verbose_name = "图书"
        verbose_name_plural = "图书"

    def __str__(self):
        return self.title
```

▸ 懂（挑 4 个最容易错的）：
- 表名规则：`app名_模型名小写` → `library_book`。不用自己写 `db_table`。
- ★ `blank` 管**校验**（表单/接口能不能为空），`null` 管**数据库**（列能不能存 NULL）。字符串字段一般只写 `blank=True`，空就存 `""`。
- ★ `price` 用 `DecimalField` 不用 `FloatField`：浮点数算钱会出 `0.1 + 0.2 = 0.30000000000000004`。
- ★ `on_delete=models.PROTECT`：分类下还有书时禁止删分类。用 `CASCADE` 会「删一个分类，连它的书一起删」，新手最容易闯的祸。

## 阶段 7　序列化器

> **目标**：让模型对象 ↔ JSON 互相转换，并加上基础校验。
> **对应**：教学文档第 8 章。
> **产出**：`library/serializers.py`。

### STEP 7.1　写 `library/serializers.py`

▸ 完整内容（注释版见 [serializers.py](./backend/library/serializers.py)）：

```python
from rest_framework import serializers

from .models import Book, Category


class CategorySerializer(serializers.ModelSerializer):
    book_count = serializers.IntegerField(source="books.count", read_only=True)

    class Meta:
        model = Category
        fields = ["id", "name", "book_count", "created_at"]
        read_only_fields = ["id", "created_at"]


class BookSerializer(serializers.ModelSerializer):
    category_name = serializers.SerializerMethodField()

    class Meta:
        model = Book
        fields = [
            "id",
            "title",
            "author",
            "price",
            "stock",
            "category",
            "category_name",
            "created_at",
        ]
        read_only_fields = ["id", "created_at"]

    def get_category_name(self, obj):
        return obj.category.name if obj.category else "未分类"

    def validate_price(self, value):
        if value < 0:
            raise serializers.ValidationError("价格不能为负数")
        return value

    def validate_stock(self, value):
        if value < 0:
            raise serializers.ValidationError("库存不能为负数")
        return value
```

▸ 懂：
- **两个方向**：读 = 模型 → JSON；写 = JSON → 校验 → 模型。同一个类管两件事。
- `source="books.count"`：`books` 是外键的 `related_name`，`.count` 翻译成 `SELECT COUNT(*)`。所以列表里每个分类会多一条 COUNT 查询（数据量大时是 N+1）。
- ★ `SerializerMethodField` 会自动去找 `get_<字段名>` 方法，方法名写错就静默返回 `null`。
- ★ `validate_stock` 里的中文提示**实际不会出现**：`PositiveIntegerField` 自带 `min_value=0` 校验，在第 2 步就拦住了，DRF 返回的是「请确保该值大于或者等于 0。」。保留它是为了演示写法。

## 阶段 8　Celery 异步任务

> **目标**：把一个耗时操作丢到后台执行，Web 请求立刻返回。
> **对应**：教学文档第 13 章。
> **产出**：`library/tasks.py` + 一个跑着的 worker 进程。

### STEP 8.1　确认配置已经写好

阶段 4 已经完成，检查三处：

| 位置 | 必须有 |
| --- | --- |
| `config/__init__.py` | `from .celery import app as celery_app` |
| `config/celery.py` | `app.config_from_object("django.conf:settings", namespace="CELERY")` |
| `settings.py` | `CELERY_BROKER_URL` / `CELERY_RESULT_BACKEND` / `CELERY_TASK_TRACK_STARTED` |

▸ 懂：这三处缺任何一处，worker 要么起不来，要么找不到任务，要么状态永远停在 PENDING。

### STEP 8.2　写 `library/tasks.py`

▸ 内容：

```python
import time
from decimal import Decimal

from celery import shared_task
from django.db.models import F, Sum

from .models import Book


@shared_task
def generate_stock_report(delay_seconds=2):
    time.sleep(delay_seconds)

    total_titles = Book.objects.count()
    total_stock = Book.objects.aggregate(total=Sum("stock"))["total"] or 0
    total_value = (
        Book.objects.aggregate(total=Sum(F("stock") * F("price")))["total"]
        or Decimal("0")
    )

    return {
        "total_titles": total_titles,
        "total_stock": total_stock,
        "total_value": str(total_value),
    }
```

▸ 懂：
- `time.sleep(2)` 是**故意**的：本地只有十几条数据，不 sleep 任务瞬间完成，你就看不到 `PENDING → STARTED → SUCCESS` 的过程。真实项目里换成导出 Excel、调第三方接口。
- ★ 返回值必须能被 JSON 序列化（dict / list / str / int）。`Decimal` 不能，所以 `str(total_value)`。
- ★ 参数也一样，不能传模型对象、`datetime`。
- `Sum(F("stock") * F("price"))`：乘法交给 MySQL 算，不用把 100 万行查进 Python 再循环。

## 阶段 9　视图

> **目标**：把「数据」和「接口」连起来。这一阶段写 6 类视图。
> **对应**：教学文档第 9 章（ViewSet）、第 11 章（N+1）。
> **产出**：`library/views.py`（先写「无缓存版」，缓存留到阶段 12 加）。

### STEP 9.1　先看清这个文件要写什么

| 类 | 继承 | 作用 | 接口 |
| --- | --- | --- | --- |
| `HealthView` | `APIView` | 健康检查 | `GET /api/health/` |
| `CategoryViewSet` | `ModelViewSet` | 分类增删改查 | `/api/categories/` 6 个 |
| `BookViewSet` | `ModelViewSet` | 图书增删改查 | `/api/books/` 6 个 |
| `StockReportTaskView` | `APIView` | 提交异步任务 | `POST /api/tasks/report/` |
| `TaskStatusView` | `APIView` | 查任务状态 | `GET /api/tasks/{id}/` |

▸ 懂：
- `APIView`：自己写 `get()` / `post()`，完全掌控。
- `ModelViewSet`：声明 `queryset` + `serializer_class`，自动拥有 list / create / retrieve / update / partial_update / destroy **6 个动作**，一行路由都不用写。

### STEP 9.2　写 `library/views.py`（第一版：能跑就行）

▸ 完整内容：

```python
from celery.result import AsyncResult
from django.db import connection
from django.db.models import ProtectedError
from rest_framework import status, viewsets
from rest_framework.exceptions import ValidationError
from rest_framework.response import Response
from rest_framework.views import APIView

from .models import Book, Category
from .serializers import BookSerializer, CategorySerializer
from .tasks import generate_stock_report


class HealthView(APIView):
    """GET /api/health/ —— 一次告诉你 Django / MySQL / Redis 谁挂了。"""

    def get(self, request):
        try:
            connection.ensure_connection()
            db_ok = True
        except Exception:
            db_ok = False

        try:
            from django.core.cache import cache
            cache.set("library:health", "ok", timeout=10)
            redis_ok = cache.get("library:health") == "ok"
        except Exception:
            redis_ok = False

        status_text = "ok" if db_ok and redis_ok else "degraded"
        return Response(
            {"status": status_text, "db": db_ok, "redis": redis_ok},
            status=(
                status.HTTP_200_OK
                if status_text == "ok"
                else status.HTTP_503_SERVICE_UNAVAILABLE
            ),
        )


class CategoryViewSet(viewsets.ModelViewSet):
    """分类的增删改查：/api/categories/"""

    queryset = Category.objects.all()
    serializer_class = CategorySerializer
    search_fields = ["name"]
    ordering_fields = ["id", "name", "created_at"]
    ordering = ["id"]

    # 分类数量少，前端下拉框要一次拿全 → 单独关掉分页
    pagination_class = None

    def perform_destroy(self, instance):
        try:
            instance.delete()
        except ProtectedError:
            raise ValidationError({"detail": "该分类下还有图书，不能删除"})


class BookViewSet(viewsets.ModelViewSet):
    """图书的增删改查：/api/books/"""

    serializer_class = BookSerializer
    search_fields = ["title", "author"]
    ordering_fields = ["id", "title", "price", "stock", "created_at"]
    ordering = ["-id"]

    def get_queryset(self):
        queryset = Book.objects.select_related("category").all()

        category_id = self.request.query_params.get("category")
        if category_id:
            try:
                queryset = queryset.filter(category_id=int(category_id))
            except (TypeError, ValueError):
                queryset = queryset.none()

        return queryset


class StockReportTaskView(APIView):
    """POST /api/tasks/report/ —— 提交异步任务，立刻返回 task_id。"""

    def post(self, request):
        task = generate_stock_report.delay()
        return Response({"task_id": task.id}, status=status.HTTP_202_ACCEPTED)


class TaskStatusView(APIView):
    """GET /api/tasks/{task_id}/ —— 查任务状态和结果。"""

    def get(self, request, task_id):
        result = AsyncResult(task_id)
        payload = {"task_id": task_id, "status": result.status}

        if result.successful():
            payload["result"] = result.result
        elif result.failed():
            payload["error"] = str(result.result)

        return Response(payload)
```

▸ 懂（5 个关键点）：
- **健康检查必须 try/except**。不包，数据库一挂这个接口自己就 500 了，监控拿不到「谁挂了」的信息。
- **返回 503 而不是 500**：503 = 依赖不可用，500 = 代码有 bug。K8s / Nginx 看到 503 会摘机器。
- ★ `CachedListMixin` 此时还没写，所以 `CategoryViewSet` / `BookViewSet` 直接继承 `ModelViewSet`。阶段 12 会改成 `CachedListMixin, viewsets.ModelViewSet`。
- ★ `BookViewSet` 故意**不写** `queryset = ...` 类属性，而是写 `get_queryset()`。因为「按分类筛选」要读本次请求的参数，类属性在启动时就固定了，拿不到 `self.request`。
- ★ `select_related("category")`：不加的话，序列化 12 本书会访问 12 次 `book.category.name`，加上就是 1 条 JOIN SQL。这就是 N+1 问题。
- `?category=abc` 走 `except` 返回空集，而不是让 MySQL 报类型错误变成 500。

### STEP 10.1　写 `library/urls.py`

▸ 内容：

```python
from django.urls import include, path
from rest_framework.routers import DefaultRouter

from .views import (
    BookViewSet,
    CategoryViewSet,
    HealthView,
    StockReportTaskView,
    TaskStatusView,
)

router = DefaultRouter()
router.register("categories", CategoryViewSet, basename="category")
router.register("books", BookViewSet, basename="book")

urlpatterns = [
    path("health/", HealthView.as_view(), name="health"),

    # ★ 固定路径必须写在动态路径前面！
    path("tasks/report/", StockReportTaskView.as_view(), name="task-report"),
    path("tasks/<str:task_id>/", TaskStatusView.as_view(), name="task-status"),

    path("", include(router.urls)),
]
```

▸ 懂：
- `router.register()` 一次生成 6 条路由，不用手写。
- `DefaultRouter` 还额外送一个 **API 根页面**（浏览器访问 `/api/` 能看到所有接口的链接），非常适合手动测试。
- ★★ **顺序是致命的**：如果把 `tasks/<str:task_id>/` 写在 `tasks/report/` 前面，请求 `/api/tasks/report/` 会被当成 `task_id="report"`，接口永远返回 `PENDING`。这个 bug 极难发现。
- ★ `path("", include(router.urls))` 放最后：它包含空路径的根页面，会吃掉所有没匹配上的请求。
- ★ 忘写 `.as_view()` 会报 `TypeError: view must be a callable`。

```python
REST_FRAMEWORK = {
```

▸ 看：价格从高到低。

**④ 按分类筛选 + 组合**



▸ 看：第二条输出 `0`。

▸ 懂：`category=abc` 是用户在地址栏乱改出来的 → `get_queryset()` 里 `int()` 失败 → `queryset.none()` 返回空集，**HTTP 还是 200**。这是「用户输入错误」而不是「服务器故障」，不该 500。

### STEP 12.2　在 views.py 顶部补 2 个 import

▸ 敲：在 [views.py](./backend/library/views.py) 的 import 区确认有这两行（没有就加上）：

### STEP 12.3　写「版本号 + 拼 key + Mixin」三件套

▸ 敲：把下面这段放在 `HealthView` **之前**（也就是 import 之后、第一个视图类之前）：

```python
# ------------------------------------------------------------
# 缓存版本号：写操作后换一个新时间戳，旧 key 自然失效
# ------------------------------------------------------------
CACHE_VERSION_KEY = "library:cache_version"
LIST_CACHE_TIMEOUT = 30


def get_cache_version():
    """读当前版本号；不存在就初始化一个并返回。"""
    version = cache.get(CACHE_VERSION_KEY)
    if version is None:
        # 纳秒时间戳几乎不会重复，不用加锁做「读-改-写」
        version = time.time_ns()
        # timeout=None → 永不过期（版本号本身不能过期）
        cache.set(CACHE_VERSION_KEY, version, timeout=None)
    return version


def bump_cache_version():
    """换一个新版本号，让所有旧的列表缓存立即失效。"""
    cache.set(CACHE_VERSION_KEY, time.time_ns(), timeout=None)


def build_cache_key(prefix, request):
    """拼出唯一 key：library:books:版本号:/api/books/?page=1&search=Python"""
    return f"library:{prefix}:{get_cache_version()}:{request.get_full_path()}"


class CachedListMixin:
    """给 ViewSet 的 list() 加缓存，写操作后自动失效。

    子类只需设一个类属性 cache_prefix = "books" / "categories"。
    """

    cache_prefix = "list"

    def list(self, request, *args, **kwargs):
        key = build_cache_key(self.cache_prefix, request)

        # 1) 先看缓存
        cached = cache.get(key)
        if cached is not None:
            return Response(cached)

        # 2) 没命中 → 走父类（ModelViewSet）的完整流程：查库、分页、序列化
        response = super().list(request, *args, **kwargs)

        # 3) 写回缓存。分页时是 dict，关分页时是 list，别套 dict()
        cache.set(key, response.data, timeout=LIST_CACHE_TIMEOUT)
        return response

    def perform_create(self, serializer):
        serializer.save()
        bump_cache_version()

    def perform_update(self, serializer):
        serializer.save()
        bump_cache_version()

    def perform_destroy(self, instance):
        instance.delete()
        bump_cache_version()
```

▸ 懂（三个最关键的点）：
1. **失效不是删除 key，而是换版本号**。旧 key 长得像 `library:books:1700000000:/api/books/`，新版本号一换，读缓存时拼出来的 key 就变了，旧 key 再也没人访问，30 秒后自动过期。这样**不需要 `SCAN` + 批量 `DEL`**（那既慢又容易删错）。
2. **`perform_create` 里必须自己调 `serializer.save()`**。DRF 原本的 `perform_create` 就是干这个的，你覆写了它却不调，数据根本不会进库。
3. **`response.data` 不能套 `dict()`**。开启分页时它是 `{count, results}`，关闭分页时（分类）它是 `[{...}]`，套 `dict()` 遇到列表直接 `ValueError`。

### STEP 12.4　把两个 ViewSet 的父类改掉（★ MRO 顺序别写反）

▸ 敲：把继承改一行：

```python
# 改前
class CategoryViewSet(viewsets.ModelViewSet):
class BookViewSet(viewsets.ModelViewSet):

# 改后
class CategoryViewSet(CachedListMixin, viewsets.ModelViewSet):
class BookViewSet(CachedListMixin, viewsets.ModelViewSet):
```

▸ 懂：Python 按 **MRO**（方法解析顺序）**从左往右**找方法。`CachedListMixin` 写在左边，它的 `list()` / `perform_*` 才能盖住 `ModelViewSet` 里的同名方法。**写反了不会报错，但缓存永远不生效** —— 这是本项目最容易踩、最难受的坑。

### STEP 12.5　给「删除分类」补上 400 提示（顺手把 500 修掉）

▸ 敲：在 `CategoryViewSet` 里加这个方法（覆盖 Mixin 里的同名方法）：

```python
from django.db.models import ProtectedError
from rest_framework.exceptions import ValidationError

class CategoryViewSet(CachedListMixin, viewsets.ModelViewSet):
    ...

    def perform_destroy(self, instance):
        try:
            instance.delete()
        except ProtectedError:
            # 外键是 on_delete=PROTECT，分类下还有书时数据库拒绝删除
            raise ValidationError({"detail": "该分类下还有图书，不能删除"})
        bump_cache_version()
```

▸ 懂：如果不管，Django 抛的 `ProtectedError` 会一路冒到最外层 → 变成 **500 Internal Server Error**。用户只看到「服务器出错」，其实是自己操作不当。翻译成 `ValidationError` → DRF 返回 **400** + 中文原因。

```python
"""python manage.py seed_demo —— 灌入演示数据（可重复执行）。"""
from decimal import Decimal

from django.core.management.base import BaseCommand

from library.models import Book, Category


class Command(BaseCommand):
    help = "写入演示用的分类和图书数据（可重复执行）"

    def handle(self, *args, **options):
        # ---------- 1. 分类 ----------
        category_names = ["技术", "小说", "历史", "心理"]
        categories = {}
        for name in category_names:
            # get_or_create：有就取、没有就建；返回 (对象, 是否新建)
            category, _ = Category.objects.get_or_create(name=name)
            categories[name] = category

        # ---------- 2. 图书 ----------
        # (书名, 作者, 价格字符串, 库存, 分类名)
        books = [
            ("Python 编程从入门到实践", "Eric Matthes", "89.00", 12, "技术"),
            ("Django 企业开发实战", "黄永祥", "99.00", 6, "技术"),
            ("深入理解计算机系统", "Randal E. Bryant", "139.00", 3, "技术"),
            ("活着", "余华", "45.00", 20, "小说"),
            ("百年孤独", "加西亚·马尔克斯", "55.00", 8, "小说"),
            ("三体", "刘慈欣", "68.00", 15, "小说"),
            ("人类简史", "尤瓦尔·赫拉利", "68.00", 10, "历史"),
            ("万历十五年", "黄仁宇", "42.00", 5, "历史"),
            ("明朝那些事儿", "当年明月", "358.00", 2, "历史"),
            ("被讨厌的勇气", "岸见一郎", "49.80", 9, "心理"),
            ("思考，快与慢", "丹尼尔·卡尼曼", "79.00", 7, "心理"),
            ("非暴力沟通", "马歇尔·卢森堡", "39.00", 11, "心理"),
        ]

        for title, author, price, stock, category_name in books:
            # update_or_create：按 title 找，找到就更新，找不到就建
            Book.objects.update_or_create(
                title=title,
                defaults={
                    "author": author,
                    "price": Decimal(price),   # 金额用 Decimal，别用 float
                    "stock": stock,
                    "category": categories[category_name],
                },
            )

        # ---------- 3. 打印结果 ----------
        self.stdout.write(
            self.style.SUCCESS(
                f"演示数据已准备完成：{Category.objects.count()} 个分类，"
                f"{Book.objects.count()} 本图书"
            )
        )
```

▸ 懂：
- `get_or_create` / `update_or_create` 是「**幂等**」的关键 —— 命令跑 10 遍，数据还是 4 个分类 12 本书，不会越跑越多。
- 价格用 `Decimal("89.00")` 而不是 `89.00`（float）。金额字段用 float 会出现 `0.1 + 0.2 = 0.30000000000000004` 这种事故。
- `self.stdout.write(self.style.SUCCESS(...))` 比 `print` 规范：能加颜色、能被测试捕获。**注意别写成「已写入 4 个分类」这种硬编码文案** —— 用 `count()` 才是真实值。

▸ 懂（三个必须记住的点）：

### STEP 15.2　script：data / computed / mounted

▸ 敲：在模板下面加 `<script>`：

```js
import { http } from './api'

export default {
  name: 'App',

  data() {
    return {
      health: null,
      healthError: '',
      notice: '',

      categories: [],
      newCategory: '',

      books: [],
      total: 0,
      page: 1,
      pageSize: 5,        // ★ 必须和后端 PAGE_SIZE 一致
      search: '',
      filterCategory: '',

      form: { title: '', author: '', price: 0, stock: 0, category: null },

      editingId: null,
      editDraft: { title: '', author: '', price: 0, stock: 0, category: null },

      reportTask: null,
      reportRunning: false
    }
  },

  computed: {
    healthText() {
      if (this.healthError) return `请求失败：${this.healthError}`
      if (!this.health) return '加载中...'
      return JSON.stringify(this.health, null, 2)
    },
    totalPages() {
      return Math.max(1, Math.ceil(this.total / this.pageSize))
    },
    reportText() {
      if (!this.reportTask) return '尚未生成报表'
      return JSON.stringify(this.reportTask, null, 2)
    }
  },

  mounted() {
    // 三个请求同时发出，不必排队
    this.loadHealth()
    this.loadCategories()
    this.loadBooks()
  },

  methods: {
    // 下一节开始填
  }
}
</script>
```

▸ 懂：
- **`data` 必须是函数**。写成对象 `data: {...}` 会让同一组件的多个实例共享数据；写函数则每个实例各有一份。
- **`computed` 有缓存**：依赖的 `data` 没变就不重算。所以「由 data 推导出来的值」（总页数、格式化文本）都放这里，不要放 methods。
- **`mounted` 只执行一次**：模板渲染成真实 DOM 之后触发，适合放「页面一打开就要有」的初始请求。

### STEP 15.3　方法组 1：健康检查 + 分类

▸ 敲：把 `methods: {}` 填成：

```js
methods: {
  // ---------- 工具 ----------
  formatTime(value) {
    return value ? value.replace('T', ' ').slice(0, 19) : ''
  },
  money(value) {
    // 后端 Decimal 序列化成字符串 "39.00"，先 Number() 才能 toFixed
    return `¥${Number(value || 0).toFixed(2)}`
  },
  showError(err) {
    const detail = err && err.response && err.response.data
    if (detail && detail.detail) {
      this.notice = `操作失败：${detail.detail}`
    } else {
      this.notice = `操作失败：${err.message}`
    }
  },

  // ---------- 健康检查 ----------
  async loadHealth() {
    this.healthError = ''
    try {
      const { data } = await http.get('/health/')
      this.health = data
    } catch (err) {
      this.healthError = err.message
    }
  },

  // ---------- 分类 ----------
  async loadCategories() {
    // 分类接口关了分页，返回的直接是数组
    const { data } = await http.get('/categories/')
    this.categories = data
  },

  async addCategory() {
    const name = this.newCategory.trim()
    if (!name) return
    this.notice = ''
    try {
      await http.post('/categories/', { name })
      this.newCategory = ''

    }

    this.notice = ''

        this.filterCategory = ''
        this.page = 1
      }
      await this.loadCategories()
      await this.loadBooks()
      this.notice = `分类「${category.name}」已删除`
    } catch (err) {
      this.showError(err)
    }
  },

  // 后面的方法继续加...
}
```

### STEP 15.6　方法组 4：行内编辑（草稿机制，这是本项目的核心设计）

▸ 敲：

```js
  startEdit(book) {
    // ★ 复制一份到 editDraft，绝不能直接绑 book 本身
    this.editingId = book.id
    this.editDraft = {
      title: book.title,
      author: book.author,
      price: Number(book.price),   // 后端给的是字符串 "39.00"
      stock: book.stock,
      category: book.category
    }
  },

  cancelEdit() {
    // 只清 editingId，表格显示的还是 books 里的原始数据 → 界面自然恢复
    this.editingId = null
  },

  async saveEdit(id) {
    if (!this.editDraft.title.trim()) {
      this.notice = '书名不能为空'
      return
    }
    this.notice = ''
    try {
      await http.patch(`/books/${id}/`, {
        title: this.editDraft.title.trim(),
        author: this.editDraft.author.trim(),
        price: this.editDraft.price || 0,
        stock: this.editDraft.stock || 0,
        category: this.editDraft.category || null
      })
      this.editingId = null
      await this.loadBooks()
      await this.loadCategories()
      this.notice = '保存成功'
    } catch (err) {
      this.showError(err)
    }
  },
```

▸ 看：点某行的「编辑」→ 这一行变成输入框；改了值点「取消」→ 恢复原样；再点「编辑」改完点「保存」→ 提示「保存成功」，表格显示新值。

▸ 懂（**这是本项目最初的定制需求**）：
- 直接 `v-model="book.title"` 会让用户**一边打字表格就一边变**（Vue 响应式），点「取消」根本回不去。
- 用 `editDraft` 这个独立对象承接，**只有点「保存」发 PATCH 成功后才生效**。这就是「先编辑，点保存才真正同步」的实现。
- 用 `PATCH` 不用 `PUT`：`PUT` 是全量替换，`PATCH` 只改传的字段。

### STEP 15.7　方法组 5：Celery 异步报表 + 轮询

▸ 敲：

```js
  async runReport() {
    this.notice = ''
    this.reportRunning = true
    try {
      const { data } = await http.post('/tasks/report/')
      // 先显示「排队中」，用户才知道点到了
      this.reportTask = { task_id: data.task_id, status: 'PENDING' }
      await this.pollReport(data.task_id)
    } catch (err) {
      this.showError(err)
    } finally {
      // ★ finally：不管成功失败，按钮都要恢复可用，否则一次报错就永久禁用
      this.reportRunning = false
    }
  },

  async pollReport(taskId) {
    // 最多查 12 次，每次间隔 700ms（约 8.4 秒）
    for (let i = 0; i < 12; i += 1) {
      // 把 setTimeout 包成 Promise，才能 await
      await new Promise((resolve) => setTimeout(resolve, 700))

      const { data } = await http.get(`/tasks/${taskId}/`)
      this.reportTask = data

      if (data.status === 'SUCCESS' || data.status === 'FAILURE') return
    }
  }
```

▸ 看：点「生成库存报表」→ 按钮变「生成中...」→ 一两秒后下面出现：

```json
  "status": "SUCCESS",
```

▸ 懂：
- 如果一直停在 `PENDING` 查满 12 次 —— **99% 是终端 B 的 Celery worker 没开**（回阶段 8 启动）。
- 轮询是「简化版」：真实项目会用指数退避或 WebSocket，并在页面切走时停止。

## 附录 D　出错速查表

> 遇到报错先在这里搜关键词。**搜不到再去 [教学文档.md](./教学文档.md) 附录 D**（那边按「错误原文」索引，更全）。

| 报错 / 现象 | 最可能的原因 | 怎么办 |
| --- | --- | --- |
| `ModuleNotFoundError: No module named 'MySQLdb'` | `config/__init__.py` 没写 PyMySQL 伪装，或写在了错误的位置 | 回阶段 4.2，确认 `pymysql.install_as_MySQLdb()` 在 `config/__init__.py` 里，且在建立连接前执行 |
| `Access denied for user 'django'@'%'` | 业务账号没授权 / 密码错 | 回阶段 1.2 重新 `GRANT` + `FLUSH PRIVILEGES` |
| `Can't connect to MySQL server on '127.0.0.1:3307'` | 容器没起，或端口写成了 3306 | `docker ps`；确认 `DATABASES` 里 `PORT` 是 `3307` |
| `Redis 连接失败` / `ConnectionError` | 密码没转义 / 端口错 / 库号错 | 密码里 `@` 要写成 `%40`；端口 `6380` |
| `django.core.exceptions.ImproperlyConfigured: Requested setting CACHES...` | `.env` 没被加载 / `load_dotenv` 位置不对 | 回阶段 4.4.1，`load_dotenv(BASE_DIR / ".env")` 要在读 `os.getenv` 之前 |
| `Unknown command: 'seed_demo'` | `management/` 或 `commands/` 缺 `__init__.py` | 回阶段 13.1，两个空文件都要有 |
| `TemplateDoesNotExist` / 白屏无报错 | `index.html` 的 `<div id="app">` 被删了，或 `main.js` 路径不对 | 检查 `index.html` 和 `<script type="module" src="/src/main.js">` |
| 浏览器控制台 `Failed to load module script` | `@vitejs/plugin-vue2` 装成了 Vue 3 的 `@vitejs/plugin-vue` | 回阶段 14.2 检查 `package.json`，重装 |
| `You are using the runtime-only build of Vue...` | `main.js` 里写了 `template: '<App/>'` | 改成 `render: (h) => h(App)` |
| 接口 404，但 curl 后端是通的 | `vite.config.js` 里多写了 `rewrite` | 删掉 `rewrite` 那一行 |
| 接口 400 `Invalid HTTP_HOST header` | 代理漏了 `changeOrigin: true` | 回阶段 14.4 补上 |
| 接口 404 `/apibooks/`（注意少了个斜杠） | `http.get('books/')` 少了开头的 `/` | 改成 `http.get('/books/')` |
| `Invalid HTTP_HOST header` 且是直接访问 8001 | `ALLOWED_HOSTS` 没加 `127.0.0.1` | `settings.py` 里补 `ALLOWED_HOSTS = ["127.0.0.1", "localhost"]` |
| 列表一直是旧数据，改了看不到 | `CachedListMixin` 写在了 `ModelViewSet` 后面（MRO 顺序反了） | 回阶段 12.4，Mixin 必须写在**前面** |
| 新增报错 `save() prohibited` / 数据没进库 | 覆写了 `perform_create` 但没调 `serializer.save()` | 回阶段 12.3 |
| 缓存里出现 `ValueError: dictionary update sequence...` | 对列表 `response.data` 套了 `dict()` | 直接 `cache.set(key, response.data, ...)` |
| 删除分类 500 | 没捕获 `ProtectedError` | 回阶段 12.5，加 `try/except` + `ValidationError` |
| 分页「上一页」显示第 0 页 | 按钮没加 `:disabled="page <= 1"` | 回阶段 15.1 的 pager 部分 |
| 搜索后看到空列表 | 搜索时没把 `page` 重置为 1 | `doSearch()` 里加 `this.page = 1` |
| 编辑时「取消」也把值改了 | `v-model` 直接绑了 `book.title`，没走 `editDraft` | 回阶段 15.6 |
| 报表一直 `PENDING` | Celery worker 没启动 / 改了 `tasks.py` 没重启 | 终端 B 重启 worker |
| `celery: command not found` | 没激活 venv | `source .venv/bin/activate` |
| `Port 8001 is already in use` | 上一个 runserver 没退干净 | `lsof -i :8001` 找到 PID 后 `kill`，或换终端重开 |
| `EADDRINUSE: 5174` | 已有一个 Vite 在跑 | 关掉旧的，或确认是不是 project1 占了 5173 |
| 中文变成 `\u4e2d\u6587` | 这是 JSON 转义，**不是乱码** | 正常现象；`python3 -m json.tool` 会原样显示 |
| `POST /api/books` 少尾斜杠返回 500 | `APPEND_SLASH` 只对 GET 做 301，POST 会直接报错 | **所有 URL 结尾都必须带 `/`** |
| `?category=abc` 返回 500 | 没做 `int()` 的异常处理 | 回阶段 11，用 `try/except` + `queryset.none()` |
| `Decimal` 无法 JSON 序列化 | 直接把 `Decimal` 塞进 `Response` | `str(total_value)` 转成字符串 |
| `update_or_create` 越跑数据越多 | 用了 `create()` 而不是 `update_or_create()` | 回阶段 13.2 |
| 改了 `settings.py` 不生效 | runserver 有时不会因为 settings 改动自动重载 | `Ctrl+C` 重启终端 A |

## 结语

到这里，你应该已经**亲手**把一个「Django + DRF + Celery + Redis + MySQL + Vue 2.7」的全栈项目从空目录跑起来了。

回头看一遍这份文档的结构，其实就是真实开发的顺序：

```
环境 → 数据库 → 依赖 → 骨架 → 配置 → 模型 → 后台 → 序列化 → 异步 → 视图 → 路由
     → 分页搜索 → 缓存 → 种子数据 → 前端骨架 → 组件 → 联调 → 可重建
```

**这份手册负责「怎么做」，[教学文档.md](./教学文档.md) 负责「为什么」。**

建议的使用节奏：

| 你在干什么 | 看哪份 |
| --- | --- |
| 第一次搭、照着敲 | 本文（施工手册） |
| 某一步报错了，想知道原理 | 教学文档对应章节 |
| 想复习某个知识点（比如 MRO、缓存穿透） | 教学文档 |
| 换机器重建、环境崩了 | 本文阶段 17 + 附录 B |
